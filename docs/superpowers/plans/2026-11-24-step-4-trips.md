# Step 4: Trips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A renter collects gear from several owners into a trip and sees, group by group, its live price, deposit and availability.

**Architecture:** A `trips` API module owns two tables and calls batch service functions in `listings` and `identity`. Marks, groups and totals are computed on read. The app adds trip screens and reuses search and the listing page for adding gear.

**Tech Stack:** Hono, Zod, Drizzle 0.45 with raw SQL, Postgres/PostGIS, Expo Router, TanStack Query.

**Spec:** `docs/spec/04-trips.md` (with `docs/spec/00-overview.md`). Rule numbers below refer to it.

## Global Constraints

- Branch `step-4-trips`. No new dependency. Do not start step 5.
- Commit only once the owner has asked for commits; otherwise skip the commit steps.
- No committed migration is edited. Tests use the local Postgres; nothing is mocked.
- Every `/trips/:id` handler starts with the ownership check: 404 unknown, 403 another renter's.
- Service functions take `tx` first. `trips` reads no table of `listings` or `identity`.
- `address` and `exact_point` are never selected. Coordinates and origins are never logged or put in a URL.
- Money is integer cents, CAD. Dates are `YYYY-MM-DD`, read from SQL with `::text`.
- Check current Hono, Drizzle and Expo Router docs before using an API not already used in this repo.

## Review Focus

Each is pinned by a test in the task named.

- A listing whose dates are already taken is added: accepted, and shown as `unavailable` (Task 2, Task 3).
- A double tap sends two adds at once: one item, both responses succeed (Task 2).
- A trip has started, and an item is added with its default dates: 400 (Task 2).
- A trip has no items: 200, no groups, zero totals (Task 3).
- A paused listing has lost its price and pickup location: still listed, null price and distance, no crash (Task 3).

```sql
create table public.trips (
  id uuid primary key default gen_random_uuid(),
  renter_id uuid not null references public.users (id),
  name text not null check (char_length(name) between 1 and 60),
  start_date date not null,
  end_date date not null,
  status text not null default 'draft' check (status in ('draft', 'submitted')),
  origin_point extensions.geography(Point, 4326),
  created_at timestamptz not null default now(),
  check (end_date >= start_date)
);
create index trips_renter_id_idx on public.trips (renter_id, created_at desc, id desc);

create table public.trip_items (
  id uuid primary key default gen_random_uuid(),
  trip_id uuid not null references public.trips (id),
  listing_id uuid not null references public.listings (id),
  start_date date not null,
  end_date date not null,
  daily_price_cents_at_add integer not null check (daily_price_cents_at_add > 0),
  created_at timestamptz not null default now(),
  unique (trip_id, listing_id),
  check (end_date >= start_date)
);

alter table public.trips enable row level security;
alter table public.trip_items enable row level security;
grant select, insert on public.trips to api;
grant update (status) on public.trips to api; -- `for update` on a trip needs an update grant
grant select, insert, delete on public.trip_items to api;
```

### Task 3: Read a trip

**Interfaces**
- Consumes: `ownTrip`, `listingFacts`.
- Produces: in `identity/service.ts`, `ownerSummaries(tx, ids: string[]): Promise<Map<string, { id; display_name: string | null; rating_avg: number | null; rating_count: number }>>`; in `listings/service.ts`, `takenItemIds(tx, items: { id; listing_id; start_date; end_date }[]): Promise<Set<string>>` (one query: a block overlaps `daterange(start, end, '[]')`); in `trips/service.ts`, `getTrip(tx, storage, userId, tripId): Promise<TripDetail>`; in shared, `tripDetailSchema`:

```ts
tripSchema.extend({
  currency: z.literal('CAD'),
  price_cents: int, deposit_cents: int,
  groups: z.array(z.object({
    owner: { id, display_name, rating_avg, rating_count },
    start_date, end_date, days: int, distance_m: int.nullable(),
    price_cents: int, deposit_cents: int,
    items: z.array(z.object({
      id, listing_id, title, photo_url: nullable,
      mark: z.enum(['available', 'unavailable', 'price_changed']),
      daily_price_cents: int.nullable(), daily_price_cents_at_add: int,
      line_total_cents: int.nullable(), deposit_cents: int,
    })),
  })),
})
```

The object shapes above are Zod shorthand.

- [ ] **Step 1: Write failing tests.**
  - `groups`: same owner and dates → 1 group of 2; different dates → 2; same dates and different pickup locations → 2; two owners → 2.
  - `marks`: `available`; `unavailable` with an owner block, a `rental` block, a paused listing, an archived listing, and an item moved to `day(0)` with `ownerPool`; `price_changed` after a rise and after a drop; `unavailable` when both apply. A block that ends the day before the item starts leaves it `available`.
  - `totals`: 3 days at 2500 with deposit 10000, plus 3 days at 1000 with deposit 5000, one group → price 10500, deposit 15000. Add a second owner, 1 day at 4000 with deposit 2000 → trip 14500 and 17000. Block the 1000 item → group 7500 and 10000, trip 11500 and 12000. A changed price uses the live price.
  - `paused with no price and no pickup location`: 200, the item is `unavailable` with null price, line total and distance.
  - `empty trip`: 200, `groups` is `[]`, both totals 0.
  - `distance`: equals the rounded PostGIS distance from the snapped origin to the public point; null without an origin.
  - `owner`: the group shows the display name, rating average and count written with `ownerPool`.
  - `privacy`: the raw response text contains neither `"address"` nor `"exact_point"`, nor the seeded address; every `lat` and `lng` in it belongs to `origin_point`.
  - `ownership`: a second user gets 403; an unknown trip gives 404.
- [ ] **Step 2: Run and see it fail.**
- [ ] **Step 3: Implement.** `mark` is `unavailable` when the status is not `active`, the price is null, the start is not after `todayInToronto()`, or the id is in `takenItemIds`; else `price_changed` when the live and added prices differ. Read items ordered by `start_date, created_at, id`; groups keep first-appearance order, keyed on owner, dates and pickup location. Days use `countedDays`.
